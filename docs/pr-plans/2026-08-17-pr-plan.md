### Phase 2 driver — provider-aware prompt caching (from `docs/cachedinput`)

Goal: **reduce Cathedral's actual LLM COGS** when a user performs multiple generations against the same project/context.

**Business rule (hard constraint):** cache savings belong to Cathedral. Do NOT reduce the customer's generation charge because a provider cache hit occurred. Customer billing continues using Cathedral's normal published input/output rates.

Internally, separately track the true provider cost using:
- normal input tokens
- cached-read input tokens
- cache-write input tokens
- output tokens
- tool costs

This lets caching increase Cathedral's margin without changing user-facing pricing.

## Phase 2 — Provider-Aware Prompt Caching (cost optimization)

### Why this matters (from `docs/cachedinput`)

The reference spec at `docs/cachedinput` (commit `6d4c471`, 238 lines) sets out the cost-saving vision: cache the **stable** portion of every generation's prompt against the project identity so a project's Nth generation reuses ~80% of the prior generation's input tokens. Customer charge stays normal; only Cathedral's margin improves.

### Design intent (from `docs/cachedinput`)

Refactor prompt assembly conceptually into 4 parts:

1. **Craft instructions** — Cathedral writing behavior, container instructions (general + per-container).
2. **Stable project context** — premise, characters, relationships, setting/world rules, themes, motifs, story spark, prompt-pack/project-level instructions, other long-lived project context.
3. **Current story state** — cumulative character state, plot threads, continuity facts, open loops, latest ending state.
4. **Current generation request** — generate/regenerate/continue/remix, previous output, terminal beat, current section, current writing task, other volatile data.

**Stable prefix is deterministic.** No timestamps, request UUIDs, random ordering, or transient values appear before the cache boundary.

Initial cache boundary: **Craft + Stable Project Context → break → Story State + Current Request**. Single break is enough until a provider API makes multiple-breaks materially simpler.

Provider-side implementation:
- **OpenAI**: stable project-scoped `prompt_cache_key`, explicit caching/breakpoint (`cache_control` markers).
- **Anthropic, Gemini**: stub providers, real adapters later.

**Token accounting:** `uncached = total input − cached reads − cache writes`, clamped at zero. Add cache-write usage/pricing where required.

**Billing:** keep two calculations separate:
- **Customer charge** uses Cathedral's normal generation pricing. NEVER discount for a cache hit.
- **Actual provider COGS** uses provider's real reported usage:
  `uncached × normal rate + cached reads × cached rate + cache writes × cache-write rate + output × output rate + tool costs`.

**Preflight:** keep assuming zero cache savings (cache hit is not guaranteed, only count it after the provider responds).

### PR-372 — Deterministic Prefix + OpenAI Cache Economics (Phase 2 PR 2)

**Goal:** add caching on top of Prompt Schema v1 without changing generation behavior. Same semantic prompt, same outputs, same customer charge per generation — but Cathedral's provider COGS drops when OpenAI's cache hits, so margin improves. **PR-371 (cache-aware accounting + telemetry) is absorbed into this PR** — the billing-separation + cached-token-accounting fixes live here alongside the cache wiring.

**Scope:** backend only (generate-story + provider + model capability config). No iOS. **Telemetry columns may require a small DB migration — allow it.**

**Files:**
- `supabase/functions/generate-story/index.ts` — refactor `buildPrompt` to always return `{ stableBlocks, volatileBlocks }`. Provider-agnostic shape. No semantic change vs Prompt Schema v1.
- `supabase/functions/generate-story/_provider.ts` — extend `OpenAI` provider with cache support; add an `OpenAI` accounting path that returns `{ uncachedInputTokens, cachedInputTokens, cacheWriteInputTokens, outputTokens }`.
- `supabase/functions/generate-story/_generation_models.ts` — replace `cache_supported: boolean` with `cacheMode: "none" | "automatic" | "explicit"` (extensible for Anthropic / Gemini later).
- `supabase/functions/generate-story/_credits.ts` (or equivalent) — separate customer charge math from provider COGS math. Customer charge uses total input at normal rate; provider COGS uses the cached-read / cache-write split.
- `supabase/migrations/<date>_cache_economics_telemetry.sql` (NEW, allowed) — extend `generation_usage_events` with `uncached_input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `provider_cogs_cents`, `customer_revenue_cents`, `margin_cents` if not already present.

**Semantic structure (same regardless of provider cache support):**

```ts
buildPrompt(payload) => {
  stableBlocks:   PromptBlock[],
  volatileBlocks: PromptBlock[],
}
```

- Non-caching providers send both blocks normally (concatenate).
- Caching providers send the same content plus provider-specific cache metadata.
- The semantic content of the prompt is identical between cache and no-cache paths — only metadata differs.

**Stable prefix (byte-identical for the same `projectId` + canon + prompt-pack):**
- writing / craft instructions
- canonical project characters
- relationships
- themes
- motifs
- spark
- setting
- ending intent
- stable prompt-pack instructions

**Volatile suffix (every call differs):**
- Section Contract (title, summary, POV, container invariants)
- current project / story state (characters, plot threads, continuity facts, open loops, ending state)
- `terminalBeat`
- `previousOutputText`
- generation action / current request

**Section title + summary MUST live in the volatile Section Contract — not inside `promptPack.notes` (PR-360-Z already fixed this; PR-372 preserves the fix).**

**Determinism (regression tests):**
- Same stable project inputs (`projectId`, `outlineId`, canon, prompt-pack) → byte-identical stable prefix.
- Changing `terminalBeat`, `previousOutputText`, `beatLabel`, section, or model → only the volatile suffix changes; stable prefix unchanged.
- No `Date.now()`, `crypto.randomUUID()`, request IDs, or transient values in the stable path.
- Stable-prefix JSON ordering is fixed (the schema is the stable contract).

**OpenAI specifics:**
- Set `prompt_cache_key: cath:proj:${projectId}:v1` on the request.
- **Do NOT add Anthropic-style `cache_control: { type: "ephemeral" }` markers.** OpenAI uses the project-scoped key + automatic prefix matching; explicit per-message markers are an Anthropic pattern, not OpenAI.
- Model capability: `cacheMode: "none" | "automatic" | "explicit"` (replaces `cache_supported: boolean`). OpenAI models use `"automatic"`; future Anthropic models will use `"explicit"`. Extensible without re-plumbing.

**Billing separation (load-bearing rule — do not violate):**

- **Customer charge** = `totalInputTokens × uncachedInputRate + outputTokens × outputRate` (Cathedral's normal rates; **never** reduced because OpenAI returned cached tokens). Cache savings are Cathedral's margin, not a discount to the customer.
- **Provider COGS** = `uncachedInputTokens × normalRate + cachedInputTokens × cachedRate + cacheWriteInputTokens × cacheWriteRate + outputTokens × outputRate + toolCost`.
- **Margin** = `customerRevenue − providerCOGS`.

**Fix existing cached-token accounting (current bug):**
OpenAI's `totalInputTokens` includes cached input. Therefore:
```
uncachedInputTokens = totalInputTokens - cachedInputTokens
```
**Do not** count total input as uncached and then add cached tokens on top — that double-counts.

**Preflight** continues to assume zero cache savings (cache hit is not guaranteed; only count it after the provider responds).

**Telemetry (`generation_usage_events` — small migration allowed if columns missing):**
- `total_input_tokens`
- `uncached_input_tokens`
- `cached_input_tokens`
- `cache_write_input_tokens` (nullable; some providers don't report)
- `output_tokens`
- `provider_cogs_cents`
- `customer_revenue_cents`
- `margin_cents`

**Acceptance criteria:**
- stable-prefix determinism tests pass (same inputs → byte-identical stable prefix).
- Same prompt behavior before vs after caching refactor (output text unchanged on smoke test; customer debit unchanged).
- Repeated same-project calls show `cached_input_tokens > 0` on the second+ call within OpenAI's cache TTL window.
- Customer debit does **not** fall on cache hit.
- Provider COGS **does** fall on cache hit.
- Margin therefore improves on cache hit.
- No double-counting of cached tokens (`uncached + cached == total`).

**Sequence:** PR-360-Z ships → smoke test on TestFlight → freeze Prompt Schema v1 → PR-372 builds on it.

**M/d/T:** iOS Build (passes unchanged; no iOS code) → Supabase Deploy (workflow_dispatch — applies migration + redeploys edge functions) → TestFlight Deploy → smoke test on TestFlight confirming `cached_input_tokens > 0` on the second generation within the same project.

**Estimated size:** ~180 lines net (edge function + provider + tests + small migration).

### New rules observed today (added to docs/ios-build-error-catalog.md as #7 and #8)

**#7 — `@MainActor` from non-isolated context.** Marking a singleton or helper as `@MainActor` makes all its methods MainActor-isolated. Calling from a URLSession callback, non-MainActor Task, or any async-non-isolated context produces `expression is 'async' but is not marked with 'await'`. Fix pattern: drop `@MainActor` + use `NSLock` for thread safety, OR make it an `actor`, OR pass the dependency into the call site. Pre-PR survey must grep all call sites of any new `@MainActor` class.

**#8 — SwiftData `@Relationship` cache is SHARED across all entity references.** Re-fetching the parent (`StoryArc`) via `FetchDescriptor` does NOT bypass the cache for the child collection. The correct pattern: fetch the CHILD rows directly via `FetchDescriptor<ChildType>(predicate: ...)`. Don't traverse the relationship. This is a CLASS of bug, not a one-off. Apply proactively to any sync/edge function that reads `entity.beats` / `entity.children` / `entity.attachments`.

### Failed fix attempts documented for future-me

1. **`try? modelContext.refresh(arc)`** — does not exist on SwiftData `ModelContext`. It's a Core Data API (`NSManagedObjectContext.refresh(_:mergeChanges:)`). Compile error: `value of type 'ModelContext' has no member 'refresh'`. Don't assume Core Data APIs work in SwiftData.
2. **`FetchDescriptor<StoryArc>` re-fetch** — the fresh `StoryArc` still shares the SAME `@Relationship` cache for `beats`. The deleted beat is still in `arc.beats` after the re-fetch. Doesn't bypass the cache.
